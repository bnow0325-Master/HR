# 2026-11-07 HR 대표 전용 근태·휴가·출장 알림 사전 검증

## 지시와 책임

대표실의 2026-11-07 직접 개발·운영 배포 지시를 확인했다. CHRO가 요구사항/HR 구현/수용 판정을, CTO가 API 계약·독립 행동검증·배포파일·통합 검증을 맡았다. 기능 PR은 HR #114이며 운영 배포 완료 기록이 아니다.

## 변경

- HR 원장 저장/승인 상태 전이와 같은 트랜잭션에서 별도 `HrNotificationOutbox`를 만든다. 실제 채팅 호출은 응답 뒤 후속 작업과 매분 재시도로 분리한다.
- 대표는 `operations`, 직원 본인 확인은 `work`와 별도 멱등 키를 사용한다. 좌표·휴가 사유·결재 메모를 대표 알림에 넣지 않는다. 기존 본인 수신 중단 정책은 유지한다.
- 최근 60초 같은 유형의 동시/중복 출퇴근을 직원행 잠금으로 차단한다. 자정을 넘는 퇴근과 취소 뒤 재퇴근은 보존한다.
- HTTP 202만으로 전송 완료로 처리하지 않는다. `chatOk:true`와 유효 messageSeq가 있어야 SENT가 되며 실제 roomId/messageSeq를 대표 전용 진단에서 대조한다.
- 매일 09:00 KST 당일 요약, 월요일 주간 요약 한 건, 빈 당일 SKIPPED, 대표 ADMIN 전용 진단 화면을 추가했다.
- 신규 scheduler 파일만 runner 이미지에 포함했다. 비노우톡과 WorkBoard 소스/권한/데이터/배포는 바꾸지 않는다.

## 확인한 사실

- 운영 HR 직원원장과 로그인된 비노우톡 `auth/me`의 대표 사내 계정·관리자 역할이 일치한다.
- 인증된 비노우톡 관리자 방 메타데이터에서 대표와 시스템 두 참여자의 direct 방 한 개를 확인했다. 개인 메시지 본문은 이 계정 확인 근거로 수집하지 않았다.
- 비노우톡 공개 health는 정상이다. 운영 정적/API 링크는 `eda7dc7-20261107-1220-album-unread`이며 이 링크 정보와 실제 컨테이너 실행 증거는 구분한다.
- HR `/opt/bnow/hr/current` 링크는 `66869b0-approval-notifications`이지만 실제 Compose 컨테이너 경로·이미지로 확정하지 않았다. 이전 배포 문서에는 `/opt/bnow/hr-releases/...` 경로도 있어 승인된 preflight가 필요하다.
- 일반 계정으로 비노우톡의 보호 환경파일 중 운영 수신자/시스템 계정 두 항목만 읽으려 했으나 OS Permission denied였다. 다른 명령·계정·sudo로 재조회하지 않았다. 운영 환경 설정의 실측 완료로 보고하지 않는다.

## 로컬 검증

- `npm run check`: TypeScript와 Next16 운영 빌드 통과. 빌드 전용 비운영 DB URL을 썼으며 운영 인증정보를 복사하지 않았다.
- 규칙·수신자 3건, 실제 route/module에 가짜 인증/롤백 가능한 DB/네트워크 경계를 주입한 행동 26건, scheduler 통신 7건: 총 36건 통과.
- 실제 MariaDB 잠금/실패 원자성 2건은 로컬에서 명시적으로 SKIP. CI의 임시 `hr_ci@localhost/bnow_hr`에만 허용했고 CI 단계에 추가했다. 이 결과는 별도로 확인한다.
- 비노우톡 기존 inbound/직원채팅 API 테스트 64건 통과. 계약 관련 운영 소스와 같은 파일을 재사용하며 비노우톡 변경 배포는 없다.
- `preflight.sh`, `deploy.sh`의 bash 구문, `git diff --check` 통과.
- 주간 경계 테스트에서 처음 기대했던 KST timestamp를 기존 달력 날짜의 UTC 자정 저장 규약에 맞게 수정했다. 운영 시간대 장애로 분류하지 않는다.
- `SKIPPED`가 대기 건수에 포함되던 문제, 대표 ADMIN 검증, 응답 전 발송 지연을 리뷰에서 보완했다.
- 첫 CI 실제 DB 시험에서 outbox 테이블 누락을 발견했다. 새 SQL이 레거시 PostgreSQL 디렉터리에 있었으나 `prisma.config.ts`는 `prisma/migrations-mariadb`를 사용했다. 활성 MariaDB 경로로 옮기고 배포의 격리 SQL 경로도 수정했다. 실패 원자성 시험은 테이블 존재와 길이 초과 오류 `P2000`까지 확인하여 다른 실패를 성공으로 오인하지 않게 보완했다. 수정 후 CI를 다시 확인한다.

## 미완료와 운영 게이트

PR CI, 실제 MariaDB 시험, 신규 화면의 실제 브라우저 조작, 승인된 운영 preflight/전체 백업·격리복원·배포, 대표 개인방 연결 확인 및 실제 기기 푸시 수용이 남아 있다. 합성 출퇴근/휴가·출장을 운영 원장에 만들지 않는다.

기존 서버 접근 지시상 거부된 보호 경로를 권한 변경으로 우회하지 않는다. 실행 계정/파일에 대한 정식 콘솔 승인 또는 운영자 실행·증빙이 있어야 배포 파일을 실행한다. root/sudo 정책이나 별도 계정을 임의로 만들지 않는다.

실행·복원 방법과 필요한 정확한 인자는 `deploy/hr-notifications/README.md`에 있다. 스크립트는 실측 기존 이미지/경로 불일치, 미확인 webhook 목적지, 백업·격리복원 실패 시 전환 전에 멈춘다. 이후 장애에는 코드만 복원하고 새 HR 기록과 outbox는 보존한다. 아직 실제 백업 경로·배포 ID는 생성되지 않았다.
